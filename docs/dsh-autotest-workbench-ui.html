设计规范与 DSH 兼容约束

设计目标：浅色、留白充足、每阶段一屏可读。核心改动是把原界面里「步骤条 + 左侧进度栏 + 标题编号 + 面包屑」四套重复进度收敛为一列左侧阶段导航 + 一行概览；1 产品文档 / 2 设计测试用例放在左侧「准备 · 输入」组，顶部不再承载阶段切换。

DeepSeek Harness / DSH 兼容约束（必须遵守）

  1. 单个 <style data-plugin-css> 注入，键名沿用 dsh-project-autotest/flow.css；所有类名以 .dpat- 前缀隔离，不污染宿主。
  2. 所有颜色写 var(--dsw-alias-*, 浅色 fallback)。本设计稿的 :root 仅用于独立预览，移植时删除，由宿主主题接管；宿主切深色也不会破版。
  3. 不引入 CDN、外部字体、图片文件或第三方 UI 库；图标全部内联 SVG。纯 React h() 调用 + 原生 JS 即可复现，不依赖打包器新增依赖。
  4. 模型执行走宿主会话：startRun(workspaceId, locale) 下发 runPrompt 给 DeepSeek Agent。UI 不自行调用模型 API、不设计 API Key / Base URL 配置，只展示会话就绪状态与下发的指令。
  5. 执行前先 persist(project)：模型读磁盘上的 project.json，页面与磁盘必须一致。结果由模型回填，UI 只读取渲染。
  6. 文案走 locales.ts 的 zh / en 键值；宿主不可达或版本过旧时显示既有 wb.hostUnreachable / wb.hostStale 提示，不另造状态。
  7. 数据字段沿用现有模型：coverageTarget、automationLevel、cases[]（kind / technique / steps / expected / result / failReason / selfCheck）、defects[]。设计稿不新增存储字段。
  8. 左侧阶段导航是 main 区内部的 CSS 两列布局（.dpat-body），不是新增宿主侧栏；宿主 slot 注册不变：sidebar.panellist + main，cordis.patch.yml 与 dsh.client.inject 不改。
  9. 窄窗口（max-width: 900px）下左列降为顶部 2 列导航、隐藏分组与脚注，保证主区可用；这是唯一允许阶段出现在顶部的断点，桌面态一律在左侧。
